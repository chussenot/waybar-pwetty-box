# Role: docs-writer

Read first: [docs/documentation.md](../../docs/documentation.md). It is the
contract, and [`scripts/check-docs.py`](../../scripts/check-docs.py) enforces
the mechanical half of it. If a rule you want to apply is in neither, it is a
preference — say so, or add it to both.

## What each surface is for

| Surface | Answers | Fails when |
|---|---|---|
| `README.md` | **why** — the boundaries a newcomer would otherwise get wrong | it grows a reference table |
| `docs/<topic>.md` | **how** one subsystem works | the same fact appears in two of them |
| `docs/adr/NNNN-*.md` | **why this and not that** | an alternative is listed without a price |
| `docs/studies/*.md` | **what actually happened**, and the rule it produced | it reads like advice instead of evidence |
| `tiles/*/README.md` | what a producer must emit | it describes rendering instead of data |

One fact, one place. A fact worth repeating gets a link instead.

## Price every alternative

An ADR that says "rejected: too complex" has not considered the alternative; it
has dismissed it. A price is concrete and checkable:

> Rejected: the producer would then have to know the tile's layout vocabulary,
> so renaming a layout here becomes a coordinated release across two
> repositories.

If you cannot name what it would cost, you do not yet know why it was rejected —
go find out, or write down that the reason is unrecorded.

## Diagrams

Mermaid, inline in the Markdown. Diffable, renders on GitHub, no source file to
hunt for. An exported PNG of a box-and-arrow drawing is banned.

**Screenshots of rendered tiles are the exception and they are core content** —
this is a visual project, and a tile README without a picture of the tile is
missing its most useful line. One condition: the image comes out of
`pwetty render` against real data. A screenshot is evidence; a mock-up is a
claim wearing evidence's clothes.

## Front matter

`title`, `status` (`draft`|`active`|`superseded`), `date`. ADRs add
`decision-makers`. Exempt files are exempt because a *tool* rewrites them —
tile READMEs are embedded in the `.so` and printed by the CLI, `AGENTS.md` and
the `.beads`/`.agents` trees are generated by `bd`, `antithesis/` carries the
discovery tool's own schema. Do not add front matter to those; it will be
reverted by the next run of the thing that owns them.

## Before you call it done

```bash
mise run docs
```

Dead links and anchors are caught. Duplicated facts, unpriced alternatives, and
a README that has quietly become a manual again are not — those are yours.

## Commit discipline

Docs commits follow the same rules as code: conventional, scoped
(`docs(adr):`, `docs(tiles):`), body explains why. If a run teaches this role
something — a rule that keeps getting broken, a distinction that keeps getting
missed — edit this file in that same commit. A role brief that never changes is
one nobody is reading.
